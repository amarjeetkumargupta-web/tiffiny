# Architecture and Design Decisions (DECISIONS.md)

This document records all architectural choices, assumptions, and tradeoffs made while engineering **Tiffiny** (Tiffin & Mess Food Subscription & Ordering Platform).

---

## 1. State Management: Riverpod
- **Decision**: Chosen `flutter_riverpod` (v2.6+) over BLoC.
- **Rationale**: Riverpod offers compile-time safety, seamless dependency injection, reactive caching (`autoDispose`, `family`), zero boilerplate for streaming Firestore snapshots, and clean mockability for unit testing without relying on `BuildContext`.

---

## 2. Navigation & Guard System: GoRouter
- **Decision**: Implemented `go_router` with reactive auth state refresh listening directly to `authProvider`.
- **Route Guard Strategy**:
  1. **Unauthenticated**: Only access Welcome, Phone Login, and OTP Verification screens.
  2. **Role Separation**:
     - Customer token/claim cannot access any `/partner/*` route.
     - Partner token/claim cannot access any `/customer/*` route.
  3. **Verification State**:
     - New Partners (`status: 'pending'`) can access onboarding and profile completion, but are presented with an under-review banner and blocked from public ordering visibility until verified.
  4. **Deep Linking**: All routes are declaratively structured with path parameters (`/partner/:id`, `/orders/:id`, `/subscription/:id`).

---

## 3. Two Roles, Strictly Separated Login
- **Decision**: Server-enforced role separation via Firebase Auth Custom Claims (`role: "customer"` vs `role: "partner"`).
- **Rationale**:
  - The client UI provides two distinct entry doors ("Order Food" vs "Partner Login").
  - On phone OTP verification, a Cloud Function inspects the user registry. If a phone number is registered as a customer, attempting to enter via Partner Login fails with: `"This number is registered as a customer. Please use Order Food to log in."` and vice-versa.
  - Custom claims are verified in Firestore Security Rules (`request.auth.token.role == 'customer'`), guaranteeing zero data leakage or horizontal privilege escalation.

---

## 4. Currency & Financial Arithmetic: Integer Paise
- **Decision**: All monetary calculations, Firestore fields, and Cloud Functions represent currency as integers in **paise** (1 INR = 100 paise).
- **Rationale**: Prevents floating-point rounding errors common with standard decimals. The UI handles formatting via `CurrencyFormatter.formatPaiseToInr()` with standard Indian number grouping (e.g., `₹1,20,000`).

---

## 5. Subscriptions & Meal Skip ("I'm Absent") System
- **Decision**: Cloud Function execution with Firestore Transactions for all meal skip, pause, and carry-forward operations.
- **Rules**:
  1. **Cut-off Window**: Configurable via Remote Config or `settings/global`. Default: 9:00 PM the previous evening for lunch and dinner, and 9:00 PM the previous evening for breakfast.
  2. **Carry-Forward Calculation**: Skipped meals are never lost or refunded as cash; rather, the subscription end-date is pushed forward by 1 slot per skipped meal, appended at the end of the scheduled cycle.
  3. **Max Skips**: Limited to 10 skips per 30-day cycle (configurable).
  4. **Kitchen Sync**: Live deduction in Partner Kitchen View so kitchen staff prepares exact meal counts.

---

## 6. Payment Architecture: Abstracted Gateway Layer
- **Decision**: Developed an abstract `PaymentGateway` interface implemented by `RazorpayPaymentService`.
- **Rationale**: Decouples Razorpay SDK from business widgets. If PayU, Cashfree, or Stripe is introduced in the future, only a new provider implementation is required.
- **Security**: Client only receives `order_id` generated by a Cloud Function. Client never writes to `paymentStatus: 'PAID'` directly; payment verification is authenticated by server-side webhook with HMAC SHA256 signature verification.

---

## 7. iOS-Style Fluid Design & Micro-Interactions
- **Decision**: Base Material 3 design system styled with Cupertino aesthetics:
  - SF Pro / Inter typography.
  - Spring-scale press feedback (`0.97` scale with `HapticFeedback.selectionClick`).
  - Slide-up bouncing cart pill with flying-dot animation.
  - Shimmer skeleton loaders instead of circular spinners.
  - High-contrast veg (green dot in green square) and non-veg (brown triangle in brown square) badges conforming to Indian FSSAI labeling standards.
  - Full system-based Dark Mode support with curated HSL dark palettes.
